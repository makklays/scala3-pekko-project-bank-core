
То есть пришел запрос в контроллер на url end-point и мы его отправили через входной порт в созданный нами новый актор,
после чего ждем от него ответа. А актор проверяет есть ли такой Аккаунт, если нету то создает его и отправляет ответ,
ответ отправляется дальше в контроллер и отображается в виде JSON.

Давайте резюмируем этот цикл, чтобы закрепить понимание:

1. Контроллер ➡️ Входной порт (Use Case) ➡️ Новый Актор: Контроллер принимает сырые данные, превращает их в понятную
приложению команду и через Use Case «стучится» в новый, только что заспавненный актор конкретного аккаунта.

2. Асинхронное ожидание: Контроллер «подвисает» в неблокирующем ожидания (onComplete на базе Scala Future), поток
сервера свободен и может обрабатывать другие запросы.

3. Проверка Актора: Актор просыпается, проверяет базу данных. Убедившись, что такого аккаунта нет, он:
  - Вызывает правила чистого Домена для сборки валидного объекта Account.
  - Сохраняет готовую доменную сущность в БД через Выходной порт (Repository).

4. Ответ обратно: Актор отправляет сообщение-ответ («Успех, ID такой-то») обратно в Use Case, который пробрасывает его
в контроллер.

5. JSON-клиенту: Контроллер перехватывает этот ответ, автоматически сериализует его в формат JSON (благодаря
AccountJsonSupport) и возвращает клиенту красивый ответ со статусом 201 Created.
